# Agent機能デモ 拡張案

## 目的

このドキュメントは、現行の Agent Framework ベースのデモを「プロトタイプとして次にどう伸ばすか」を整理したものです。
単なる機能列挙ではなく、以下の観点で優先順位を付けています。

- デモとして見せやすいか
- Agentらしさが強く出るか
- 現在の実装へ段階的に追加しやすいか
- 将来の業務適用に繋がるか

## 現在の実装範囲

現状のデモでは、すでに以下が実装されています。

- 単一Agentのストリーミング応答
- マルチAgent並列分析
- RAG検索連携
- AI役員会議のような役割分担型Group Chat
- セッション単位の会話履歴メモリ
- Backend主導のモデル設定とFrontend連携
- `podman-compose` による起動

## 開発ステータス

優先順位に従って順次実装を進めます。2026-03-10 時点のステータスは以下です。

| 項目 | ステータス | 備考 |
|---|---|---|
| タスク分解と実行計画の可視化 | 実装済み | 通常チャット / マルチAgent分析 / RAG検索 / AI役員会議で plan を表示 |
| Human-in-the-loop承認 | 実装済み | マルチAgent分析 / AI役員会議 / 承認対象モデルで approve / reject / revise を表示 |
| ツール実行ログと根拠表示 | 実装済み（RAG先行） | RAG検索で検索 trace と文書 evidence を回答と分離表示 |
| ファイル入力対応 | 実装済み | 各モードで `.txt/.md/.csv/.json/.pdf/.docx` を添付し、セッション文脈へ反映 |

このため、次の拡張は「Agentを呼べるか」ではなく、「Agentがどこまで自律的に仕事を進められるか」を強化する方向が適切です。

## 推奨ロードマップ

### Phase 1: すぐに効く拡張

#### 1. タスク分解と実行計画の可視化

ユーザーの要求を受けたあと、Agentが内部で以下を出すようにします。

- ゴール
- サブタスク
- 使用するツール
- 完了条件

効果:

- ただのチャットではなく「計画して動くAgent」に見える
- 後続の承認フローやツール実行とつなぎやすい

実装イメージ:

- Backendで planner agent を追加
- Frontendで「計画」パネルを追加
- 各サブタスクの状態を `pending / running / done / blocked` で表示

#### 2. Human-in-the-loop承認

Agentが以下のような操作前にユーザー承認を求める形式です。

- 外部送信
- データ更新
- 長時間ジョブ開始
- 高コストモデル利用

効果:

- 業務システムに近い安心感が出る
- 「Agentの自律性」と「人の統制」のバランスを見せられる

実装イメージ:

- Backendで承認待ち状態を保持
- Frontendに承認ダイアログを追加
- `approve / reject / revise` の3系統を持つ

#### 3. ツール実行ログと根拠表示

Agentが何をしたかを見える化します。

- どのツールを呼んだか
- どの検索語を使ったか
- どの文書を根拠にしたか
- 最終回答と根拠の対応

効果:

- デモ中の説明がしやすい
- RAGやマルチAgentの価値が伝わりやすい

実装イメージ:

- Backendイベントを structured JSON 化
- Frontendで「Answer」「Trace」「Evidence」の3ペイン表示

#### 4. ファイル入力対応

ユーザーがファイルを渡して、それをAgentが読んで処理する流れです。

- PDF要約
- 仕様書レビュー
- 議事録からToDo抽出
- 企画書への批判/賛成/統合分析

効果:

- チャットより一段上の実務感が出る
- 既存のマルチAgent分析と相性が良い

実装イメージ:

- Frontendにファイルアップロード
- Backendで一時保存とテキスト抽出
- 抽出内容を thread memory または添付コンテキストに投入

### Phase 2: Agentらしさを強める拡張

#### 5. 永続メモリ化

現在はプロセス内メモリ中心なので、以下へ保存先を移します。

- Redis
- PostgreSQL
- Blob Storage + メタデータDB

効果:

- 再起動後も会話継続可能
- セッション履歴の共有・再利用が可能

実装ポイント:

- `SessionStore` を抽象化
- `AgentThread` と会話メタデータの永続化層を分離

#### 6. Agentルーティング

入力内容から自動でAgentモードを切り替えます。

- 単純質問なら通常チャット
- 比較/論点整理ならマルチAgent分析
- 文書根拠が必要ならRAG
- 経営テーマならAI役員会議

効果:

- ユーザーがモードを選ばなくてもAgent側が最適化できる
- 「オーケストレーション」感が強まる

実装イメージ:

- router agent を先頭に配置
- 既存の各ワークフローを backend 内で分岐呼び出し

#### 7. 評価・採点Agent

最終回答の品質を別Agentが検査する拡張です。

- 目的に答えているか
- 根拠が十分か
- 曖昧な表現がないか
- 次に必要な情報が明示されているか

効果:

- Agentが自分の出力を改善する流れを見せられる
- デモとして「一回出して終わり」にならない

実装イメージ:

- `critic agent` を末尾に追加
- 一定スコア未満なら再実行

### Phase 3: 業務PoC寄りの拡張

#### 8. 非同期ジョブ化

長時間かかる処理をバックグラウンドジョブとして扱います。

- 大量文書の分析
- レポート生成
- 複数ソース横断の調査

効果:

- 実運用に近い見せ方ができる
- 通知や進捗管理と組み合わせやすい

実装イメージ:

- ジョブID発行
- ステータスAPI
- 進捗イベント配信

#### 9. 監査ログとコスト集計

Agent利用の運用に必要な観点です。

- 使ったモデル
- トークン数
- 実行時間
- 呼び出しツール
- セッション単位の履歴

効果:

- PoCから本番移行を検討しやすい
- モデルルーティング最適化の根拠になる

#### 10. 権限制御と共有ワークスペース

複数ユーザー利用を前提にした拡張です。

- ログイン
- チーム単位の会話履歴
- データアクセス制御
- 共有ナレッジベース

効果:

- 実業務の組織利用に近づく
- ただしデモ段階では優先度は低め

## デモとして特に見せやすいユースケース

### 1. 企画レビューAgent

入力:

- 企画書
- 要件メモ

処理:

- 批判的観点
- 前向き観点
- 実行計画
- リスク整理

見せ場:

- マルチAgent
- 根拠
- 承認フロー

### 2. 規程照会 + 社内相談Agent

入力:

- 社内規程への質問
- 具体的な業務相談

処理:

- RAG検索
- ポリシー違反の有無確認
- 次アクション提案

見せ場:

- 根拠付き応答
- ルーティング
- 判断根拠の可視化

### 3. 経営会議シミュレーションAgent

入力:

- 経営課題
- 参考資料

処理:

- CEO/CTO/CFO/COOで議論
- 実行計画化
- Criticがレビュー

見せ場:

- 複数ロール
- 長めのワークフロー
- 計画とレビューの往復

## 現行リポジトリでの実装優先順位

このリポジトリに対して、現実的には次の順で進めるのがよいです。

1. 計画可視化
2. ツール実行ログ/根拠表示
3. Human-in-the-loop承認
4. ファイル入力
5. 永続メモリ化
6. Agentルーティング

理由:

- 既存の streaming UI と相性が良い
- Agent Framework のワークフロー拡張として自然
- デモ品質の向上に直結する
- そのまま業務PoCへ繋げやすい

## 最小追加で効果が大きい提案

もし短期間で1つだけ追加するなら、以下を推奨します。

### 推奨: 計画可視化 + 承認フロー

この組み合わせがよい理由:

- Agentが考えていることが見える
- 人が最終的に制御していることも見える
- デモの説明が非常にしやすい
- ファイル入力や外部ツール連携へ自然に拡張できる
